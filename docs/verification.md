# 取得結果の確認方法

バックアップは「実行できた」ではなく「**欠落していないこと**」の確認が必要です。
ここでは、その確認手順をまとめます。

## 1. 実行後にログを確認する

「詳細ログ」を開き、次の行を確認してください。

| 行 | 意味 |
|---|---|
| `本体にある写真・動画 N ファイル / 合計 X GB` | iPhone側で見つかった総数 |
| `☁ iCloudにしか無い写真: なし` | iCloud上のみの原本が無いこと。ある場合は件数と一覧が出ます |
| `新規ダウンロード N 件（残りは取得済みをスキップ）` | 今回取得した数 |
| `アルバム振り分け N/N` | アルバムへのリンク作成が完了したこと |
| `✅ 完了` | 正常終了 |

**次のいずれかが出た場合は、まだ揃っていません。**

- `⚠ N 件は取得できませんでした → 一覧: _取得失敗一覧.txt`
- `※ N 個がまだ揃っていません`
- `☁ iCloudにしか無い写真: N 個`

いずれも**原因を解消してもう一度実行**すれば、不足分だけを取得します。

## 2. 出力されるレポート

保存先に、状況に応じて次のファイルが作られます。**0件になった場合は自動的に削除**されるので、
残っていれば「まだ解消していない」ことを意味します。

| ファイル | 内容 |
|---|---|
| `_取得失敗一覧.txt` | ダウンロードに失敗したファイル。再実行で再試行されます |
| `_iCloudにしか無い写真.txt` | 端末に原本が無い写真と、その所属アルバム |
| `_メディアタイプ診断.txt` | 種類判定の元データ（件数がiPhoneと合わない時に共有してください） |
| `schema_dump.txt` | DBの構造を特定できなかった場合の診断情報 |

## 3. 件数を突き合わせる

**PowerShell** で、保存先のファイル数を数えられます（`E:\iPhoneAlbums` は自分の保存先に読み替え）。

```powershell
# キャッシュ（実体）の数 = iPhone内の実ファイル数と一致するはず
(Get-ChildItem "E:\iPhoneAlbums\_cache_DCIM" -Recurse -File).Count
```

これがログの `本体にある写真・動画 N ファイル` と一致すれば、実体は揃っています。

アルバムごとの件数は次のとおりです。

```powershell
Get-ChildItem "E:\iPhoneAlbums" -Directory |
  Where-Object { $_.Name -notlike "_*" } |
  ForEach-Object { "{0} : {1}" -f $_.Name, (Get-ChildItem $_.FullName -Recurse -File).Count }
```

> Live Photos は1項目が2ファイル（`.HEIC` と `.MOV`）になるため、
> **iPhoneの表示件数より多くなります**。これは正常です。

## 4. 容量が想定より大きく見える場合

エクスプローラーのフォルダサイズは、**ハードリンクを1件ずつ数える**ため実際より大きく表示されます。
実測例では、実体166.8GBのバックアップが540GB（約3.2倍）と表示されました。

実際に共有されているかは次で確認できます。

```powershell
fsutil hardlink list "E:\iPhoneAlbums\<アルバム名>\<ファイル名>"
```

複数のパスが表示されれば、同じ実体を共有しています（＝ディスクは減っていません）。
本当の使用量はドライブのプロパティで確認してください。

> **ハードリンクは独立したコピーではありません。** ある経路から内容を**変更**すると、
> 他の経路からも変更後の内容が見えます。「複数のアルバムに現れる＝複数の独立したバックアップ」
> ではありません。編集する場合は、作業用に複製してから行ってください。
> 別ドライブへのコピーを取る場合も、コピー先では実体が展開されるため容量が必要です。

## 5. 定期的に確認したいこと

| タイミング | 確認 |
|---|---|
| 毎回 | ログに `✅ 完了` が出ること、レポートファイルが残っていないこと |
| 毎回 | iPhone側で写真やアルバムを変えたなら「アルバム情報を取り直す」にチェックしたか |
| ときどき | 実際に写真が開けること（数枚でよいので開いて確認） |
| ときどき | `_cache_DCIM` を消していないこと（消すとアルバム側のリンクが切れます） |
| ときどき | ドライブの空き容量 |

## 6. 別の場所にもコピーを持つ

本ツールが作るのは、1台のドライブ上の1つのコピーです。
ハードリンクで参照を共有しているため、**そのドライブが壊れれば全部失われます**。

重要な写真は、別のドライブやクラウドにもコピーを持つことを推奨します。
コピー先ではハードリンクが展開されるため、`_cache_DCIM` だけをコピーするのが効率的です
（アルバム構成は再実行で作り直せます）。
