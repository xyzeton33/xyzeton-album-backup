# 対応範囲と既知の制限

**確認済み・対象外・未確認**を分けて記載しています。未確認は「動かない」という意味ではなく、
**作者が検証していない**という意味です。ご利用前にお読みください。

確認環境（1台のみ）:
iPhone 11 Pro Max / iOS 26.6.2 / Windows 10・Windows 11 / Apple純正USBケーブル /
写真アプリ上 79,025項目（412アルバム）・実ファイル 84,263個・167.1GB /
ツール v3.3.0（2026-09-15に実測）

---

## メディアタイプの分類について

種類の判定は写真アプリのDB内の値を使っていますが、**この値は公式に文書化されたものではありません**。
アプリ側で「2 アルバムを確認」を押すと種類ごとの件数が出るので、
**iPhoneの「メディアタイプ」画面の件数と見比べて**ください。
食い違う場合は、保存先に出力される `_メディアタイプ診断.txt` を添えてご報告ください。

## アルバム⇔写真の対応表の特定について

写真アプリのDBでは、この対応表の名前がiOSの版によって変わります（`Z_28ASSETS` など）。
本ツールは名前ではなく**中身の性質から候補を絞り込んで**特定しますが、これは**推定**です。
未確認のDBでは誤判定の可能性が残ります。

そのため、確信が持てない場合は**処理を中断し、DBの構造を `schema_dump.txt` に書き出します**。
誤った表でアルバムを作るより、止まって報告いただくほうが安全と考えています。

## 写真データベースの整合性について

写真アプリのDB（`Photos.sqlite`）は、取得している最中にもiPhone側で更新されることがあります。
本ツールは main / `-wal` / `-shm` を1セットとして扱い、端末側の構成が変わっていれば
セットごと取り直します。

ただし、**取得中に更新されたDBの整合性まで保証するものではありません**。
[SQLite公式](https://www.sqlite.org/howtocorrupt.html)が説明するとおり、更新中の単純なコピーは
新旧が混在する可能性があります。バックアップ中はiPhoneの写真アプリを操作しないことを推奨します。

異常が疑われる場合は「アルバム情報を取り直す」にチェックして再実行してください。

## 実行中に「(応答なし)」と表示される

写真の一覧を調べている工程など、iPhoneへの問い合わせが集中する場面で、
タイトルバーに「(応答なし)」と出ることがあります。

**異常ではありません。** Windowsは、ウィンドウが数秒間反応しないとこの表示を出します。
バックアップ自体は進んでおり、画面の更新が止まっているだけです。
工程が変わると表示も元に戻ります。

**写真が多いほど長く続きます。** 実測では、写真アプリ上 79,155項目・167.6GB の環境で、
**最長で約9分**固まったままになりました（2026-09-20・v3.3.0）。
写真が数百枚程度であれば、ほとんど気になりません。

強制終了せずにお待ちください。終了してしまった場合も、
取得済みのファイルは残り、次回は続きから再開します。

表示の改善は今後の課題としています。

## 保存先ドライブが途中で切断された場合

外付けHDDが省電力で眠る、ケーブルの接触不良、電源の問題などで、
バックアップ中に保存先ドライブが見えなくなることがあります。

**工程によって挙動が違います。**

| 工程 | 切断されたとき |
|---|---|
| [3/4] 写真のダウンロード中 | 検知して最大30分待機し、復帰すれば自動で再開します |
| [4/4] アルバム別に振り分け中 | **停止します**（v3.3.0時点の制限） |

[4/4] で停止した場合、次のようなエラーが表示されます。

```
[WinError 1167] デバイスが接続されていません
[WinError 55]   指定されたネットワークリソースまたはデバイスは利用できません
[WinError 433]  存在しないデバイスを指定しました
```

**データは壊れません。** 配置済みのファイルはそのまま残ります。
ドライブが復帰したあとにもう一度「3 バックアップを始める」を押せば、
**続きから再開します**（取得済みの写真は再ダウンロードされません）。

### 予防

外付けドライブを使う場合は、事前に次の設定を確認してください。

1. **ディスクの電源を切らない**
   コントロールパネル → 電源オプション → プラン設定の変更 → 詳細な電源設定 →
   ハードディスク → 「次の時間が経過後ハードディスクの電源を切る」を **0（なし）** に

2. **USBの省電力を切る**
   デバイスマネージャー → ユニバーサルシリアルバスコントローラー →
   各「USB Root Hub」のプロパティ → 電源の管理 →
   「電力の節約のために、コンピューターでこのデバイスの電源をオフにできるようにする」のチェックを外す

3. **USBハブを経由しない**
   PC本体のポート、できれば背面ポートに直接つないでください

繰り返し切断される場合は、ケーブル・電源・接続先（SATAポート等）の
ハードウェア側に原因があることがあります。

## 本番の前に確認する（推奨）

**取得する写真の枚数を絞る機能はありません。**「3 バックアップを始める」を押すと全件が対象です。
そのかわり「2 アルバムを確認」は、**写真を1枚もダウンロードせずに** DBの解析結果だけを表示します。
まずここまで進めて、次の4点を確認してください。

| 確認すること | 見るところ |
|---|---|
| アルバムが正しく読めているか | アルバム名と件数の一覧。iPhoneの「アルバム」画面と見比べる |
| 種類の判定が合っているか | メディアタイプごとの件数。iPhoneの「メディアタイプ」画面と見比べる |
| iCloudにしか無い写真があるか | 「☁ iCloudにしか無い写真」の行。あれば先に端末へダウンロードする |
| 容量が増えない形で保存できるか | 「✅ ハードリンクが使えます」の行。出ない場合は空き容量が数倍必要 |

件数が大きく食い違う場合は、進めずにご報告ください
（保存先に出力される `_メディアタイプ診断.txt` を添えていただけると助かります）。

バックアップは途中で中止でき、再実行すれば続きから再開します。
実行後は `_取得失敗一覧.txt`（0件なら作られません）も確認してください。

## 本ツールで**できないこと**

- iPhone全体の復元用バックアップ（写真・動画の書き出し専用です）
- 連絡先・メッセージ・アプリのデータ
- PCからiPhoneへの書き戻し
- iCloudにしか無い原本の取得
- 削除された写真の復元

## セキュリティ境界について

`_album_state.json`（前回の実行結果を記録するファイル）と、Photos.sqlite内のファイルパス
（`ZDIRECTORY`/`ZFILENAME`）は、いずれも**保存先フォルダの外や、写真キャッシュの外を
指すことができないよう検証しています**（v3.2.0〜）。

v3.3.0では、保存先フォルダ**の内部**に作られたシンボリックリンク／ジャンクションも
辿らないようにしました（保存先そのものがジャンクション配下やネットワークドライブに
ある正常なケースは、これまでどおり使えます）。

これは、改変された `_album_state.json` や、細工されたPhotos.sqliteを `--db` で読み込ませる
といった限定的な状況を想定した対策です。通常のiPhone・通常の利用では発生しません。
検証は `source/tests/` の `test_album_export_security_review.py` ほかとして同梱しています。

## 免責

Appleの公式製品ではありません。iOSの更新や利用環境によって動作しなくなる場合があります。
無保証です。**いきなり全件を実行せず、まず「2 アルバムを確認」まで進めて
結果を確かめてください**（「本番の前に確認する」の節をご覧ください）。
